# The signing process

Every document a collector signs is generated by the engine, sent for signature through
DocuSign, chased from one screen, and filed back on the collector's record as an executed
PDF. Nothing is assembled by hand and nothing lives in somebody's Drafts folder.

This document is the process. The account setup is at the bottom.

## What gets signed, and when

| The sale | The paper | Signed by |
|---|---|---|
| Any sale | Invoice, which is the bill of sale | Nobody. It is a demand for payment, not a contract to negotiate |
| Any sale | Certificate of authenticity, issued with the work | The gallery only, countersigned on the certificate |
| Over the threshold (default $50,000) | Purchase agreement | The collector, then the gallery |
| On a payment plan, any amount | Purchase agreement | The collector, then the gallery |
| A work released before purchase | On approval agreement, before the work leaves | The collector, then the gallery |

The threshold is a gallery decision, not a legal line. It lives in one place,
`SIGNING_THRESHOLD_CENTS` in Vercel, and defaults to $50,000. Change the variable, redeploy,
and every screen follows.

The rule is written once in `crm/lib/signing.js`. The Signing page, Today and the morning
digest all read it, so there is no second definition to drift.

## The loop, as a rep runs it

1. The sale is invoiced in the wizard as usual.
2. If the policy needs an agreement, the sale shows up on **Signing** under "Sales that still
   need paper", and on **Today** under "Paper the gallery is waiting on". It stays there
   until an agreement is signed or at least out for signature.
3. In Finance, "Purchase agreement" generates the document from the sale: parties, the works,
   the price broken down, the deposit and balance, the terms. The rep reads it.
4. "Send for signature" puts it into DocuSign. The collector signs first, the gallery
   countersigns second, both anchored to invisible markers already drawn in the PDF.
5. DocuSign reports back to `/api/docusign-webhook` at every step: sent, opened, signed,
   declined, voided. The status lands on the document row and on the collector's timeline.
6. Anything out for three days shows as going cold. **Remind** nudges the signer, **Void**
   pulls it back so a corrected version can go out.
7. On completion the executed PDF is pulled from DocuSign and stored beside the original. The
   collector record carries it from then on.

Nothing in this loop sends itself. A person presses Send, every time. That rule holds here as
it does everywhere else in the engine.

## Before the first real signature

- **Counsel reads the templates.** They are drafted, not blessed. Until
  `AGREEMENTS_REVIEWED=1` is set in Vercel, every agreement prints a draft watermark and says
  on its face that counsel has not reviewed it. Do not send one to a collector before that.
  The clause list and the open questions are in `docs/AGREEMENT-TEMPLATES.md`.
- **Confirm the constants** in `crm/lib/agreementsPdf.js`: governing law (New York as drafted),
  late interest (1% a month), the inspection window (5 days), and whether a deposit is
  forfeited on default.
- **Bernie's signature.** Drop a transparent PNG at `crm/assets/img/signature.png` and
  redeploy, and certificates carry it.
- **Decide who countersigns.** `DOCUSIGN_COUNTERSIGNER_EMAIL` is the gallery signer. Leave it
  unset and documents come back with the collector's signature only.

## Setting up the DocuSign account

All of it under the gallery identity, `wyatt@chasecontemporary.com`, so it transfers with the
rest of the stack.

1. Create a DocuSign eSignature account with API access. Developer sandbox first: it is free
   and the integration key is promoted to production later.
2. Settings, Apps and Keys. Add an app called "Chase Engine". Copy the **Integration Key**,
   your **User ID** and the **API Account ID**.
3. In that app, generate an RSA keypair and copy the **private key**. Add a redirect URI, any
   URL you control, for the consent step.
4. Grant consent once, signed in as the API user:
   `https://account-d.docusign.com/oauth/auth?response_type=code&scope=signature%20impersonation&client_id=<INTEGRATION_KEY>&redirect_uri=<your redirect URI>`
   and press Allow. Without this, every send fails with "consent has not been granted".
5. Connect, Add configuration. URL `https://chase-engine.vercel.app/api/docusign-webhook`,
   JSON (SIM) format, events sent, delivered, completed, declined and voided, HMAC key on.
6. Put the values into Vercel and redeploy:

| Variable | What it is |
|---|---|
| `DOCUSIGN_INTEGRATION_KEY` | The app's client id |
| `DOCUSIGN_USER_ID` | The API user GUID being impersonated |
| `DOCUSIGN_ACCOUNT_ID` | The API account GUID |
| `DOCUSIGN_PRIVATE_KEY` | The RSA private key, `\n` escapes are fine |
| `DOCUSIGN_BASE` | `demo` in the sandbox, `prod` once promoted |
| `DOCUSIGN_API_BASE` | Production only, the account's base URL from Apps and Keys |
| `DOCUSIGN_CONNECT_SECRET` | The HMAC key from step 5, so webhooks are verified |
| `DOCUSIGN_COUNTERSIGNER_EMAIL` | Optional, the gallery signer |
| `SIGNING_THRESHOLD_CENTS` | Optional, defaults to 5000000, which is $50,000 |
| `AGREEMENTS_REVIEWED` | Set to `1` only after counsel has read the templates |

7. Going live needs DocuSign to promote the integration key: 20 successful envelopes in the
   sandbox and a short review by them. Start the sandbox sending early so the promotion is not
   what holds up a real sale. Until it is promoted, leave `DOCUSIGN_BASE=demo`, where envelopes
   are real but carry a sandbox watermark, so do not send one to a collector.

Until any of this exists the Signing page says plainly that it is not connected, the documents
still generate, and they can be sent by hand.
